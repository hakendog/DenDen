# DenDen 如何讀取設定與發送金鑰

日常傳送通知時，DenDen CLI 只讀取專案的訊息頻道設定、目前使用者的 DenDen 設定，以及這台電腦自己的發送金鑰。它不會掃描專案原始碼、文件、瀏覽器資料或使用者目錄中的其他檔案。

一般使用者不需要手動開啟或修改這些檔案。安裝、搬移設定與更換電腦應交給 DenDen 設定助手處理。

## 讀取順序

### 1. 專案設定

CLI 會從目前工作資料夾開始向上尋找 `.denden.json`。這個檔案只保存訊息頻道名稱、預設頻道與專案可共用的通知規則，不得包含配對秘密、Google 金鑰或其他憑證。

傳送時會依下列順序選擇訊息頻道：

1. 命令指定的 `--channel-id`。
2. `DENDEN_CHANNEL_ID` 環境變數。
3. `.denden.json` 中的 `defaultChannelId`。

如果找不到專案設定、指定的頻道不存在，或檔案含有禁止欄位，CLI 會停止，不會自行猜測。

### 2. 使用者設定

接著讀取目前使用者的 DenDen 設定。預設位置是：

```text
<使用者目錄>/.config/denden/config.json
```

設定 `XDG_CONFIG_HOME` 時，位置會改成該目錄下的 `denden/config.json`。`DENDEN_CONFIG_PATH` 可以替單次執行指定另一個完整路徑。

這份設定包含：

- Google 專案與 Firebase App 的公開識別資料。
- 私人通知頻道、配對識別資料與通知加密金鑰。
- 全域及各訊息頻道的通知偏好。
- 這台電腦的發送金鑰所在目錄。

這是私密設定檔，不應放進 Git、同步資料夾、對話或問題回報。CLI 會檢查欄位與格式，設定不完整或出現未知欄位時會拒絕傳送。

### 3. 發送金鑰

使用者設定只保存發送金鑰目錄的位置。實際金鑰檔名固定為：

```text
<發送金鑰目錄>/service-account.json
```

DenDen 會先確認目錄與檔案只有目前的電腦使用者可以讀取，再檢查金鑰是否屬於使用者設定指定的 Google 專案。專案不符、檔案格式不正確或權限過寬時都會停止。

Windows 會以檔案存取權限限制目前使用者；macOS 與 Linux 會檢查私密目錄及檔案權限。每台發送電腦都有自己的金鑰，不應從另一台電腦直接複製。

## 發送通知時會發生什麼

1. CLI 讀取並驗證專案設定與使用者設定。
2. CLI 從受保護目錄讀取這台電腦的發送金鑰。
3. Google Cloud CLI 使用該金鑰取得只適用於 Firebase Messaging 的短期存取權杖。
4. DenDen 在電腦上加密通知標題、內容與標籤。
5. CLI 使用短期權杖把密文送到使用者自己的 Firebase 專案。

長期私鑰檔案留在本機。傳送要求使用的是短期存取權杖，不是 Google 帳戶密碼，也不是初次設定時的人類管理登入。日常通知功能不能建立專案、變更權限、重新配對手機或讀取手機的 FCM 裝置權杖。

Google 接收發送要求只代表 FCM 已接受訊息，不代表手機一定收到。DenDen 不會建立遠端裝置清單，也不會從伺服器查詢手機上的收件紀錄。

## 讓另一台電腦發送通知

遠端發送目前支援 Windows、macOS 與 Linux。新電腦不能沿用另一台電腦的 `service-account.json`，而是透過設定助手取得自己的發送身分與金鑰。

新增發送電腦時，先從已設定的電腦匯出有密碼保護的一般設定包，再將設定包匯入新電腦。設定包提供 Google 專案識別資料、私人通知頻道與通知加密金鑰，但不包含任何電腦的 Google 發送金鑰。

匯入完成後，設定助手會要求使用者登入管理 DenDen 的 Google 帳戶。取得同意後，它會為新電腦建立獨立的發送身分、保存新的本機金鑰、驗證只能傳送 FCM 訊息，最後移除管理登入。新電腦必須傳送測試通知，並由使用者在手機確認結果。

完整操作步驟見[新增或停用電腦](device-management.md#新增或停用電腦)。

Android 上的 Bixby 與 Tasker 只會在同一支手機本機建立 DenDen 訊息。目前不支援把另一支 Android 手機當成遠端發送端。

## 停用或更換電腦

電腦遺失或退役時，可以只停用該電腦的發送身分，不影響其他電腦與手機。如果外洩的是配對資料或通知加密金鑰，則要更換整組配對資料，並讓保留的手機重新配對。

命令與設定格式見 [CLI 技術文件](cli.md)。一般操作見[新增與管理裝置](device-management.md)。
